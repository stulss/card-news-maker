# 배포

## 현재 상태

- 운영 주소: https://card-news-maker-beige.vercel.app/
- 배포 대상: Vite 정적 프론트엔드만 (2차에서 서버리스 함수 `api/`를 삭제했다)
- 환경변수: 없음
- 1차 제출 시점(`9c362ac`)의 배포는 야구 탭과 `/api/kbo-schedule`을 포함했다. 2차 커밋 `ef38778`을 `main`에 푸시했으므로
  Vercel이 자동 재배포했다면 `/api/kbo-schedule`은 이제 존재하지 않는 것(404)이 정상이다.
- 이후 후속 변경(내보내기 창·명령 팔레트·눈금자 등)은 아직 커밋·푸시 전이다(`작업내역_체크리스트.md` §6 참고).

## 설정

- 빌드 명령: `npm run build` (`tsc -b && vite build`)
- 출력 디렉터리: `dist`
- `vercel.json`은 **보안 헤더만** 정의한다(CSP·nosniff·Referrer-Policy·Permissions-Policy·X-Frame-Options·COOP, `/assets/*` 장기 캐시). 서버리스 함수는 없다. 한글 웹폰트는 `@fontsource`로 번들에 포함(자체 호스팅).

## 배포 전후 검증

1. `npx tsc -b`, `npm run lint`, `npm run build`를 실행한다. (Vite의 500kB 초과 청크 경고는 기존 비차단 경고)
2. 배포 후 운영 URL이 HTTP 200인지 확인한다.
3. 화면에서 `docs/검증안내서.md`의 항목(갤러리 적용, 밈 프리셋, 되돌리기, 내보내기)을 훑는다.
4. `/api/kbo-schedule`이 404인 것은 의도된 상태다.
5. 로컬에서 운영과 같은 헤더로 보려면 `npm run build` 후 `node scripts/serve-dist.mjs 4173`. `npm run test:e2e`가 CSP 위반·외부 요청 0건을 확인한다.
6. CSP를 고칠 때는 **AI 배경 제거를 반드시 직접 실행**해 본다(`blob:` 스크립트·모델 호스트가 막히면 이 기능만 조용히 실패한다).

과거 배포 500 오류의 원인과 해결(1차, 현재 코드는 삭제됨)은 `docs/트러블슈팅.md`를 참고한다.
