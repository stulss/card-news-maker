### 2.1 PDF 현황 및 계승할 우수 구조
`odd-one-out`의 제출 보고서는 과제 평가자가 15초~30초 내에 핵심을 파악할 수 있도록 매우 체계적으로 구성되어 있습니다:
- **1~3페이지**: 프로젝트 개요, 기능 안내서(조작, 상태, 단축키, 설정, 기록)
- **4~15페이지**: 카드 1~5별 핵심 기능 및 증거 (PC 검사표, 10분 연속 실행 무누수, 난이도 전/후 데이터 비교, 6종 손상값 복구, 접근성)
- **16~17페이지**: AI 3줄 (맡긴 일, 판단한 일, 말을 안 들은 일), 트러블슈팅 대표 사례 3건
- **18페이지**: 최종 상태 요약표 (카드 1~5 완료, 자체 점검 11/11, 콘솔 0건, 개인정보 0건 등)
- **19~22페이지**: 검증 안내서 (어디로 가나요, 무엇을 하나요 3단계, 통과 기준, 안 될 때 FAQ)
- **23~24페이지**: 학생 자체 점검 스크린샷 증거 (1~11번)

## 5. Claude 검토 갱신 (2026-08-24)

### 5.1 재검증 결과

`작업내역_체크리스트.md`가 "카드 4·5 완료"로 남긴 코드가 실제로 커밋되지 않은 작업 트리 변경분(레이어 패널, 템플릿 패널, 비율 전환, 텍스트 스타일 패널 등)에 걸쳐 있어 소스 코드로 직접 재확인했다.

- `src/App.tsx`에 1:1·4:5·9:16 비율 전환 버튼(`RATIO_PRESETS`), 레이어/템플릿 탭 전환, `LayerPanel`, `TemplatePanel` 연결을 확인함 — 위 표 12~17번 항목을 **구현 진행 → 충족**으로 갱신.
- `src/features/template/templateStore.ts`의 `parseTemplateBundle`이 JSON 문법 오류와 필수 필드 누락을 각각 거부하고 기존 템플릿을 보존함을 확인함.
- `npx tsc -b`, `npm run lint`(oxlint), `npm run build` 모두 오류 없이 통과함(2026-08-24).
- 카드 3(극단 입력 12종)의 구체적 테스트 로그와 카드 4·5의 검사 기록(14·17번)은 **agy의 브라우저 실검증 결과 문서**를 그대로 인용해야 한다 — Claude는 코드 정적 검증만 수행했고 스크린샷·수동 조작 기록은 생성하지 않았다.

### 5.2 모바일 반응형 점검 (design/EditorMobile.dc.html 대비)

시안은 **속성 패널 바텀시트(peek 상태)**, **하단 고정 삽입 툴바**, **레이어 패널 아이콘 토글 접힘** 세 가지 모바일 전용 패턴을 정의한다(`design/EditorMobile.dc.html` 76번째 줄 "속성 패널 바텀시트", 94번째 줄 "하단 고정 삽입 툴바" 주석).

현재 구현(`src/App.css` 428번째 줄 `@media (max-width: 900px)`)은 이 세 패턴을 구현하지 않고, 좌측 사이드바·캔버스·텍스트 스타일 패널을 세로로 쌓고 각 패널에 `max-height`만 부여하는 방식이다.

| 시안 요구 | 현재 구현 | 격차 |
|---|---|---|
| 속성 패널이 바텀시트로 하단에서 올라옴 | 세로 스택의 한 구획으로 고정 표시(`max-height: 40vh`) | 시트 드래그·peek/expand 상태 없음 |
| 삽입 액션이 화면 하단에 고정 툴바로 노출 | 헤더 툴바가 최상단에 그대로 유지(모바일 전용 재배치 없음) | 엄지 도달 범위 밖, 스크롤 시 접근 불가 |
| 레이어 패널이 아이콘 토글로 접힘 | 탭 버튼으로 레이어/템플릿 전환만 가능, 접힘 토글 없음 | 좁은 화면에서 캔버스 노출 영역이 줄어듦 |

**결론**: 모바일에서 기능은 동작하지만(레이아웃이 깨지지 않음), 시안이 의도한 모바일 전용 UX는 아직 적용되지 않았다. `작업내역_체크리스트.md` §3의 "모바일 반응형 레이아웃 적용" 항목은 계속 미완료로 유지한다. 과제 20개 체크리스트에는 모바일 전용 항목이 없으므로 **제출 채점에는 영향이 없다** — PC 검증 경로가 정상이면 제출 자체는 가능하다.

### 5.3 Phase 4(야구 탭) / Phase 5(배포) 방향 제안

과제 채점 대상인 20개 자체 점검 항목(§4)은 카드 1~5(일반 카드뉴스 편집·내보내기·템플릿)만 다루며 야구 탭(PRD 43·44장)은 포함하지 않는다. 따라서 두 Phase의 우선순위를 다음과 같이 제안한다.

1. **우선 — Phase 5(배포) 골격 준비**: 과제 제출에는 정적 빌드 결과물 또는 배포 URL이 필요할 가능성이 높다. 다만 Vercel 커넥터가 이 세션에서 미인증 상태라 실제 배포는 **사용자의 대화형 인증(`vercel login` 등)이 선행되어야** 한다. Claude가 지금 할 수 있는 일은 배포 설정 점검(빌드 명령·출력 경로 확인, 환경변수 필요 여부 재확인)까지이며, 실제 `vercel deploy` 실행은 인증 완료 후로 미룬다.
2. **다음 — Phase 4(야구 탭)는 과제 범위 밖의 보너스 기능**: PRD 43·44장에 F-30~F-33 및 백엔드 API(`GET /api/kbo-schedule`)가 이미 상세 설계돼 있어 구현 준비는 되어 있다. 하지만 20개 채점 항목에 없고, 구단 엠블럼 수집·크롤링 백엔드라는 새 작업 범위가 추가되므로 **제출 마감 이후 여유가 있을 때 착수**하는 편이 안전하다.
3. 사용자가 우선순위를 바꾸고 싶다면(예: 야구 탭을 제출물에 포함) 명시적으로 알려주면 Codex에게 F-30 탭 전환부터 순서대로 인계한다.
