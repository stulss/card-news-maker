# 07. GitHub 레퍼런스 분석 — photocraft · vectorcraft · lightcraft (2026-11-02)

사용자가 지정한 저장소의 기능을 조사해 이 프로젝트(React + Konva 웹 카드뉴스 메이커)에 맞는 것만 골라 적용한 기록.

## 1. 조사 방법과 한계

| 항목 | 내용 |
|---|---|
| 대상 | `storytold/photocraft`(포토샵류), `storytold/vectorcraft`(일러스트레이터류), `storytold/lightcraft`(라이트룸류) — 모두 Rust·egui·wgpu로 만든 데스크톱 앱(웹 빌드 포함), 라이선스 **MIT OR Apache-2.0** |
| 읽은 것 | 각 저장소 README와 `docs/` 일부(vectorcraft의 `target-app-parity.md`·`ui-parity.md`), crates 폴더 목록. **소스 코드는 읽지 않았다** — 기능→파일 대응은 크레이트 이름에서 추정한 것이다 |
| 코드 재사용 | **없음.** 언어(Rust)가 달라 코드를 가져올 수 없고, 기능 아이디어만 Konva/React로 새로 구현했다 |
| `morluto/rea` | 사용하지 않았다. REA는 바이너리·앱 번들·HAR 등 **배포된 산출물을 역공학**하는 MCP 서버(`npx rea-agents setup`)이며 소스 저장소의 기능 분석에는 맞지 않는다. 설치 시 에이전트(MCP) 설정을 수정하고 외부 도구를 실행할 수 있어, 필요성이 낮은 상태로 설치하지 않았다. 대신 README·문서를 직접 읽었다 |
| 신뢰도 | 각 README의 수치(스타 수·패리티 %)는 저장소 스스로의 주장이다. 긴 문서의 뒷부분은 요약본이었다 |

## 7. 설치한 앱 3종을 rea로 분석하고 적용한 것 (2026-11-02)

### 7.1 방법과 한계
| 시도 | 결과 |
|---|---|
| `rea inspect-rust-binary` (의존성 목록) | 빌드에 cargo-auditable 메타데이터가 없어 비어 있음(해시·컴파일러 커밋 정도만 반환) |
| `rea inspect` (개요) | 분석 엔진(Ghidra·Hopper·IDA·Kuna)이 없어 `provider_unavailable` |
| `rea inspect-pe-resources` | 입력 파일 상한 64MB 초과(앱은 100~170MB) |
| **실제로 쓴 방법** | ① 실행 파일에 내장된 문자열 직접 추출(VectorCraft는 한국어 번역 5,168개 내장, PhotoCraft·LightCraft는 거의 없음) ② 동봉 문서(README·ASSETS·라이선스) ③ **사용자가 실행해 둔 앱 창을 창 단위로 캡처**(Win32 PrintWindow, 해당 3개 창만)해 UI를 직접 확인 |

- 정리하면 **rea 단독으로는 이 앱들의 기능 목록을 뽑지 못했다.** 분석 엔진을 연결하면 디컴파일은 가능하지만, 170MB 러스트 GUI 앱에서 카드뉴스에 필요한 기능을 얻기에는 비용 대비 효과가 낮아 연결하지 않았다.
- 코드·이미지·에셋은 **가져오지 않았다.** 기능 아이디어와 UI 패턴만 참고해 Konva/React로 새로 구현했다(원 코드 라이선스는 MIT OR Apache-2.0).

### 7.2 화면에서 확인한 UI 패턴
- **PhotoCraft**: 왼쪽 도구 막대, 오른쪽 패널을 탭 묶음(색상·견본·그레이디언트·패턴 / 속성·조정 / 레이어·채널·패스)으로 구성, 시작 화면에 "새 문서 Ctrl+N · 열기 Ctrl+O"와 끌어다 놓기 안내.
- **VectorCraft**: 시작 화면의 "새 파일 빠르게 시작"(소셜 정사각형 1080×1080 등 크기 카드), 하단 상태줄의 상황별 조작 힌트, 오른쪽 아이콘 레일 + 패널.
- **LightCraft**: 오른쪽 패널이 접고 펼 수 있는 섹션(Light·Color·Effects·Detail·Optics…)이며 슬라이더 오른쪽에 값 표시, 상단 `Auto / B&W / HDR / Reset`, 하단 "Copy Edit Settings", 하단 필름스트립.

## 8. 실행 중인 앱 창을 직접 조작해 확인한 것 (2026-11-02)

사용자가 세 앱을 실행해 둔 상태에서, 해당 창만 앞으로 가져와 클릭·키 입력을 보내고 창 단위로 캡처했다(Win32 `SetForegroundWindow` · `mouse_event` · `SendKeys` · `PrintWindow`).
메뉴·패널을 여는 조작만 했고, 저장·삭제·가져오기·외부 링크는 누르지 않았다. 작업이 끝난 뒤 LightCraft를 원래 편집 화면으로 되돌렸다(최소화돼 있던 창은 복원해야 조작할 수 있었다).

| 앱 | 확인한 화면 | 얻은 것 |
|---|---|---|
| LightCraft | 편집 패널의 Effects 섹션(Texture·Clarity·Dehaze·Vignette…), `Shift+P` 프리셋 패널, `C` 크롭 도구 | **프리셋이 카테고리별**(B&W·Color·Film·Food·Landscape·Portrait)로 묶여 있음, 크롭 오버레이 **Thirds·Grid·Golden·Diagonal·Triangle·Spiral·None** |

### 추가로 적용한 것
| 아이디어 | 구현 |
|---|---|
| 프리셋을 카테고리로 묶기 (LightCraft) | 이미지 프리셋 18종을 흑백·컬러·필름·푸드·풍경·인물로 재구성(값은 이 프로젝트의 필터로 새로 정함). 강도 슬라이더 유지 |

## 9. 앱을 더 조작해 찾은 추가 기능 (2026-11-02)

| 앱 | 조작한 화면 | 발견 | 판단 |
|---|---|---|---|
| LightCraft | 마스킹 도구(`M`) | 마스크 종류: Object·Describe·Subject·Sky·Background·Brush·**Linear**·**Radial**·Luminance·Color. History(시계 아이콘) 패널, 하단 Copy Edit Settings | Linear/Radial → **사진 위 그라디언트 오버레이로 적용**. Subject·Sky·Background·Describe(AI 선택)는 브라우저에서 모델이 무거워 보류. History 패널은 후보 |
| VectorCraft | 새 파일 대화상자(`Ctrl+N`)의 **Social** 탭 | 프리셋: 정사각형 1080×1080, Portrait 1080×1350, Landscape 1200×630, Story 1080×1920, Tall 1000×1500, Profile Cover 1500×500, Page Cover 1640×624, Video Banner 2560×1440, Video Thumbnail 1280×720 | **크기 대화상자로 적용** |
| PhotoCraft | 새 문서 대화상자(`Ctrl+N`) | 사용자 지정 가로·세로, 방향 전환, 해상도, 사전 설정 저장 | **직접 입력·가로세로 바꾸기로 적용**(해상도·색 모드는 웹 캔버스에 무의미해 제외) |

### 적용한 것
| 기능 | 구현 |
|---|---|
| 캔버스 크기 대화상자 | 상단 ⤢ 버튼·시작 카드·명령 팔레트. 인스타그램 5종(피드 4:5·1:1·3:4·9:16·가로 1.91:1) + 다른 SNS·웹 5종(유튜브 썸네일·링크 공유 1200×630·X 헤더·페이스북 커버·핀터레스트) + 직접 입력(100~4000px, 가로↔세로 바꾸기, 비율 표시). 모든 슬라이드에 적용 (`components/size/SizeDialog.tsx`) |
| 그라디언트 확장 | `GradientFill`에 `type: "radial"`, `fromOpacity`/`toOpacity` 추가 → 투명→어두움 그라디언트와 원형 그라디언트. 배경·도형 편집기에 종류 선택과 불투명도 슬라이더 |
| 사진 위 글자용 오버레이 | 도형 탭 하단: 하단 어둡게·상단 어둡게·전체 어둡게·원형 비네팅. **가장 위의 이미지 바로 위(zIndex +0.5)에 자동 배치**해 그 위의 글자는 그대로 위에 남는다 (`features/design/overlays.ts`) |

### 후보였던 것 — 모두 구현 (2026-11-02)
| 후보 | 구현 |
|---|---|
| 작업 이력 패널 (LightCraft History) | 왼쪽 레일 `기록` 탭. 되돌리기 단계 목록을 보고 클릭으로 그 시점으로 이동, 되돌린 단계는 흐리게 표시. 단계 이름은 앞뒤 스냅샷 비교로 자동 생성(`features/history/describe.ts`) |
| 텍스트 그라디언트 | 글자 색에 단색/그라디언트(색 두 개·각도·종류·불투명도·프리셋) 선택. 스타일 복사·썸네일에도 반영 |
| 이미지를 도형으로 자르기 | 원형·별·삼각형·육각형·하트·말풍선으로 오리기. 오린 결과를 새 비트맵으로 만들어 Konva Image에 넘기는 방식(`features/design/maskImage.ts`), 테두리도 모양을 따라감 |
| 스티커 팩 확장 | 배지 7·말풍선 4·강조 6·장식 5 = 22종. 도형·글자 레이어를 그룹으로 추가(이미지 파일 없음 → 저작권 문제 없음) |
| AI 배경 제거 (LightCraft Subject/Background 마스크 대체) | `✨ AI 배경 제거` 버튼. 브라우저 안에서 Transformers.js + MODNet으로 처리, 결과는 투명 PNG로 교체(되돌리기 가능) |
