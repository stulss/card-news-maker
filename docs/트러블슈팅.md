# 트러블슈팅

> 1~4번은 1차(야구 탭) 시절 기록이다. 해당 코드는 2차에서 삭제됐지만 교훈은 유효해 남긴다. 5번부터가 2차 기록이다.

## 1. 로컬에서는 되는데 배포 API가 500

- 증상: `/api/kbo-schedule`이 `FUNCTION_INVOCATION_FAILED`를 반환했다.
- 원인: Vite 개발 서버와 달리 배포된 Node ESM은 상대 import 확장자를 요구했다.
- 해결: `api/kbo-schedule.ts`의 상대 import에 컴파일 산출물 기준 `.js`를 명시했다.
- 교훈: 서버리스 코드는 로컬 dev뿐 아니라 컴파일 산출물의 Node 실행 경로도 검증한다.

## 2. 스코어보드 배경이 단색으로만 보임

- 증상: 야구 카드의 도형 레이어가 렌더링되지 않았다.
- 원인: 템플릿 검증은 ShapeLayer를 허용했지만 공용 캔버스 렌더러가 shape 타입을 처리하지 않았다.
- 해결: `CanvasStage.tsx`에 사각형·원 렌더링을 추가했다.
- 교훈: 기능별 우회 이미지 대신 공용 렌더러의 누락을 근본 수정한다.

## 3. 지정한 한글 폰트가 적용되지 않음

- 증상: IBM Plex Sans KR을 지정했지만 브라우저가 Malgun Gothic으로 조용히 폴백했다.
- 원인: 폰트 이름만 지정하고 실제 웹폰트를 로드하지 않았다.
- 해결: `index.html`에서 Google Fonts를 로드하고 폰트 준비 완료 시 캔버스를 다시 그렸다.
- 교훈: 폰트는 CSS 선언뿐 아니라 네트워크 로드와 실제 계산 스타일을 확인한다.

## 4. 오른쪽 워터마크가 배경에 가려짐

- 증상: 홈팀 워터마크가 보이지 않았다.
- 원인: 홈팀 배경 z-index가 워터마크보다 높았다.
- 해결: 두 배경을 같은 최하위 계층에 두고 워터마크를 그 위에 배치했다.



## 5. 되돌리기를 넣었더니 레이어 순서 변경이 이력을 망가뜨림 (2차)

- 증상(잠재): 레이어를 ▲▼로 옮긴 뒤 Ctrl+Z 하면 이전 상태가 이미 바뀌어 있을 수 있었다.
- 원인: 기존 `handleMoveLayer`가 레이어 객체의 `zIndex`를 제자리에서 수정해, 되돌리기 스냅샷과 같은 객체를 공유했다.
- 해결: `reorderLayers`가 항상 새 배열·새 객체를 만들도록 바꿨다. 이후 모든 레이어 변경(이동·그룹·정렬)을 불변 방식으로 통일했다.
- 교훈: 스냅샷 기반 이력을 도입하면 상태를 제자리에서 고치는 코드를 전부 찾아 불변으로 바꿔야 한다.

## 6. 새 웹폰트를 골라도 캔버스 글자가 안 바뀜 (2차)

- 증상: 글꼴 목록에서 "주아"를 골라도 캔버스 글자가 폴백 글꼴로 보였다.
- 원인: 캔버스(Konva)는 DOM과 달리 쓰이지 않은 웹폰트를 스스로 내려받지 않는다.
- 해결: 텍스트 레이어가 쓰는 글꼴을 `document.fonts.load`로 먼저 불러온 뒤 다시 그린다(`CanvasStage`의 `fontKey` 효과).
- 교훈: 캔버스에 쓰는 폰트는 "선언"이 아니라 "로드 완료"를 확인한다(3번과 같은 계열).

## 7. 레이어 드래그 정렬이 휴대폰에서 동작하지 않음 (2차)

- 원인: HTML5 드래그앤드롭 이벤트는 터치 입력에서 발생하지 않는다.
- 해결: `⋮⋮` 손잡이에 포인터 이벤트(`setPointerCapture` + `elementFromPoint`)를 써서 마우스·터치를 한 경로로 처리하고 `touch-action: none`을 지정했다.

## 8. 원·별 도형을 끌거나 키우면 위치가 어긋남 (2차)

- 원인: Konva의 원·별·다각형은 노드 좌표가 도형의 중심인데, 레이어 데이터는 좌상단 기준이었다.
- 해결: 이동은 "노드 이동량(dx, dy)"만 레이어에 더하는 방식으로, 변형은 중심→좌상단 변환을 거쳐 저장하도록 바꿨다. 원은 `Ellipse`로 바꿔 타원도 지원한다.

상세 재현과 커밋 이력은 `작업내역_체크리스트.md` §4를 기준으로 한다.

## 9. 새로고침하면 업로드한 사진이 사라짐 (자동 저장 도입 시)

- 원인: 업로드 이미지는 `blob:` 주소라 페이지를 닫으면 무효가 되고, localStorage(≈5MB)는 사진 한 장에도 넘칠 수 있다.
- 해결: 자동 저장을 IndexedDB로 하고, 저장 시점에 `blob:` 주소를 data URL로 변환한다(같은 주소는 캐시). 복원할 때는 템플릿 JSON과 같은 검증기를 통과한 덱만 받아들인다.

## 10. 여러 장을 한꺼번에 내보내면 이미지가 빠진 장이 생길 수 있음

- 원인: 슬라이드를 전환한 직후에는 이미지가 비동기로 로드되어 캔버스에 아직 없다.
- 해결: 캔버스가 `projectId()`와 `isReady()`(보이는 이미지 레이어 수만큼 노드가 그려지고 글꼴 로드 완료)를 노출하고, 내보내기가 그 조건을 기다린 뒤 캡처한다. 내보내는 동안 진행 창으로 화면 전환을 가린다.

## 11. 세트 템플릿에 넣은 페이지 번호와 내보내기 옵션이 겹침

- 증상: ZIP의 2번 파일에 "2 / 5"가 두 번 찍혔다.
- 해결: 템플릿에서는 페이지 번호를 빼고 내보내기 옵션 하나로 통일했다.

## 12. 그라디언트를 넣었는데 단색으로 보임

- 원인: Konva는 `fill`이 지정되어 있으면 `fillLinearGradient…`보다 `fill`을 우선한다.
- 해결: 그라디언트가 있을 때는 `fill`을 아예 넘기지 않고, 없을 때만 `fill`을 넘긴다(배경·모든 도형 공통).

## 13. 그림자 색이 적용되지 않음

- 원인: 8자리 hex(`#00000066`)를 그림자 색으로 넣었는데 Konva의 색 파서가 이를 보장하지 않는다.
- 해결: 그림자 색은 `rgba(r, g, b, a)` 문자열로 저장하고, 색 피커에서는 hex를 rgba로 변환한다.

## 14. 하트·말풍선 도형을 키우면 크기가 이상하게 저장됨

- 원인: 경로(Path) 노드에는 width/height가 없어 일반 도형처럼 `width × scale`을 읽을 수 없다.
- 해결: 경로 도형은 100×100 좌표계를 scale로 늘려 그리므로 `크기 = 100 × scale`로 읽어 저장하고, 다시 그릴 때 같은 scale이 만들어지게 했다.

## 15. rea로 앱 기능 목록이 뽑히지 않음

- 증상: `rea inspect`가 `provider_unavailable`, `inspect-pe-resources`가 64MB 상한 오류, `inspect-rust-binary`가 빈 결과.
- 원인: 개요·디컴파일 계열은 분석 엔진(Ghidra·Hopper·IDA·Kuna)이 필요한데 연결하지 않았고, 대상 앱이 입력 상한보다 크며, 빌드에 의존성 메타데이터가 없다.
- 해결(우회): 실행 파일의 내장 문자열, 동봉 문서, 실행 중인 앱 창 캡처로 대신했다. 교훈: 도구가 막히면 목적(기능 파악)에 맞는 더 단순한 수단으로 바꾸고, 도구의 한계를 기록에 남긴다.

## 16. 드래그 정렬·워터마크 같은 기능의 자동 검증 기준이 틀림

- 증상: 로고 워터마크가 분명히 보이는데 "붉은 픽셀 0개"로 판정됐다.
- 원인: 진하기 70%로 배경과 섞인 색(예: G 105)이 "G<90" 기준에 걸리지 않았다.
- 해결: 투명도를 고려해 기준을 완화하고, 대조군(로고 삭제 후 0개)과 함께 비교했다. 교훈: 합성 결과를 픽셀로 검증할 때는 알파 혼합과 대조군을 같이 설계한다.

## 17. 실행 중인 앱 창을 조작하려는데 "창을 찾을 수 없음"

- 증상: 프로세스는 있는데 창 목록 조회가 비었다(LightCraft).
- 원인: 창이 **최소화**돼 있어 크기가 `-32000` 좌표의 작은 사각형으로 보고되었고, "너비 300 초과" 조건에 걸러졌다.
- 해결: 제목이 있는 최상위 창을 고른 뒤 먼저 `ShowWindow(SW_RESTORE)`로 복원하고 크기를 다시 읽는다. 포그라운드 잠금을 피하려고 Alt 키 입력 후 `SetForegroundWindow`를 쓴다.
- 교훈: GUI 자동화는 창 상태(최소화·가려짐)부터 확인하고, 조작 전후를 캡처로 검증한다.

## 18. 오버레이를 추가했더니 사진 아래로 들어가거나 글자를 가림

- 증상(가능성): 새 레이어는 맨 위에 쌓이므로 "사진 위, 글자 아래"에 있어야 하는 오버레이가 글자를 덮는다.
- 해결: 오버레이는 가장 위의 이미지 레이어 바로 위(`zIndex + 0.5`)에 삽입한다. 이미지가 없으면 맨 위에 놓고 안내 메시지로 순서를 맞추도록 알린다.
- 부수: 픽셀로 검증할 때 선택된 큰 도형의 **선택 핸들(흰 사각형)이 모서리를 가려** 측정이 틀어졌다 → 선택을 해제한 뒤 측정한다.

## 19. 개발 모드에서만 되돌리기 단계가 합쳐짐

- 증상: 방향키로 이동했는데 작업 이력에 이동 단계가 없고, 바로 앞의 "추가" 단계에 합쳐져 있었다(운영 빌드에서는 정상).
- 원인: 병합 판단용 `ref`를 상태 갱신 함수 안에서 수정했다. StrictMode(개발 모드)는 갱신 함수를 두 번 호출하므로 두 번째 호출이 첫 호출이 남긴 값을 보고 잘못 병합했다.
- 해결: 마지막 변경의 키·시각을 상태 안(`last`)에 넣어 갱신 함수를 순수하게 만들었다. 슬라이더 5번 조작은 여전히 한 단계로 합쳐지고 이동은 별도 단계로 남는다.
- 교훈: 상태 갱신 함수 안에서는 외부 값(ref·전역)을 바꾸지 않는다.

## 20. Konva Image로는 하트·별 모양으로 못 자름

- 원인: Konva의 Image 노드는 모서리 둥글기만 지원하고 임의 모양 클리핑은 없다(Group `clipFunc`로 감싸면 드래그·변형·자르기 모드 코드가 모두 복잡해짐).
- 해결: 모양대로 오려 낸 결과를 새 캔버스 비트맵으로 만들어 Image 노드에 넘긴다. 확대·위치(자르기)는 비트맵을 만들 때 반영하고, 테두리도 같은 경로로 그린다.

## 21. AI 배경 제거가 실패하는 경우
- 오프라인이거나 huggingface.co/jsDelivr에 접속할 수 없으면 모델을 받지 못해 실패한다(오류 배너로 안내, 사진은 그대로).
- 사람이 아닌 사진은 결과가 부정확할 수 있다(MODNet은 인물용).
- 다시 시도하면 처음 단계부터 재시도한다(실패한 로딩 결과를 캐시하지 않음).

## 22. 이미지를 뒤집은 뒤 크기를 바꾸면 크기가 10px로 줄어듦

- 원인: 뒤집힌 노드는 `scaleX < 0`인데, 변형 값을 읽는 코드가 `width * scaleX`를 그대로 써서 음수가 되었고 최소값(10)으로 잘렸다. 또 읽은 뒤 `scale`을 1로 되돌려서 뒤집힘도 풀렸다.
- 해결: 크기는 `abs(scale)`로 계산하고, 부호는 보존한 채 ±1로 되돌린다(`readNodeTransform`). 뒤집기는 `scale(-1)`과 `offset=상자 크기`로 상자 위치를 유지한다.

## 23. TypeScript가 `"filter" in ctx`의 else 분기를 never로 봄

- 원인: `CanvasRenderingContext2D`의 타입에는 `filter`가 항상 있어서, "없을 때" 분기가 `never`로 좁혀졌다(실제로는 Safari 일부 버전에 없음).
- 해결: 런타임 검사를 `Record<string, unknown>`으로 캐스팅한 별도 변수에 두어 두 분기 모두 컴파일되게 했다. 없으면 축소→확대로 흐림을 근사한다.

## 24. 자동 검증 선택자가 사용자가 입력한 문구와 겹침

- 증상: 텍스트 문구를 "곡선으로 휘어진 글자"로 바꾼 뒤, "곡선"이 들어간 라벨을 찾는 테스트가 문구 입력칸의 라벨을 집어 슬라이더를 못 움직였다(앱 문제 아님).
- 교훈: 테스트 선택자는 사용자 입력 문자열과 겹치지 않게 라벨의 제목 요소로 한정한다.

## 25. 운영 CSP에서 AI 배경 제거만 조용히 실패

- 증상: 개발 서버에서는 잘 되던 AI 배경 제거가, `vercel.json`의 CSP를 입힌 운영 빌드에서 모델은 내려받는데 `no available backend found … Failed to fetch dynamically imported module: blob:…`로 실패.
- 원인: Transformers.js(onnxruntime-web)가 wasm 로더를 `URL.createObjectURL`로 만든 **blob: 스크립트**로 불러오는데 `script-src`가 `'self'`뿐이었다.
- 해결: `script-src 'self' 'wasm-unsafe-eval' blob:`. 인라인 스크립트(`'unsafe-inline'`)는 여전히 허용하지 않는다. 같은 CSP로 로컬 서빙(`scripts/serve-dist.mjs`)하며 CSP 위반 로그 0건과 실제 사진의 투명 영역 42%를 확인.
- 교훈: CSP는 "화면이 열린다"만으로 검증할 수 없다. 동적 기능(AI·내보내기)을 **운영과 같은 헤더에서 실행**해야 하고, 그래서 헤더를 그대로 입히는 로컬 서버와 e2e를 만들었다.

## 26. 글꼴 자체 호스팅으로 배포물이 79MB가 됨

- 증상: `@fontsource`를 그대로 가져오니 2543개 파일·79MB.
- 원인: 한글 글꼴은 유니코드 범위별로 수백 조각이고, woff와 woff2가 둘 다 들어간다. 쓰지 않는 700 굵기도 포함.
- 해결: 빌드 플러그인 `dropWoffFallback`으로 `.woff` 대체 제거(최신 브라우저는 모두 woff2), 쓰지 않는 굵기 제거 → 1029개·51MB(이 중 26MB는 AI wasm). 조각은 해당 글자가 쓰일 때만 내려받으므로 첫 로드에는 영향이 작다.
- 교훈: 외부 의존을 없애는 대가(배포 크기)를 숫자로 확인한다.

## 27. 거부 테스트가 엉뚱한 이유로 통과 (대조군의 필요)

- 증상: "허용되지 않는 blendMode는 거부" 테스트가 처음부터 통과했는데, 같은 구조에 **허용된** 값을 넣은 대조 테스트는 실패했다.
- 원인: 손으로 만든 템플릿 JSON의 구조가 틀려(레이어는 `canvas.layers` 아래) 어떤 값을 넣어도 "형식 오류"로 거부됐다. 테스트가 blendMode 검사를 실제로는 확인하지 못했다.
- 해결: 기본 템플릿(`createDefaultTemplates`)을 복제해 필드 하나만 바꾸는 방식으로 고치고, "허용 값은 통과 / 금지 값은 거부" 쌍을 둠.
- 교훈: 거부(negative) 테스트에는 항상 같은 입력에서 통과(positive)하는 대조군을 붙인다.
