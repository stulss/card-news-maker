# 트러블슈팅

> 1~4번은 1차(야구 탭) 시절 기록이다. 해당 코드는 2차에서 삭제됐지만 교훈은 유효해 남긴다. 5번부터가 2차 기록이다.

## 1. 로컬에서는 되는데 배포 API가 500

- 증상: `/api/kbo-schedule`이 `FUNCTION_INVOCATION_FAILED`를 반환했다.
- 원인: Vite 개발 서버와 달리 배포된 Node ESM은 상대 import 확장자를 요구했다.
- 해결: `api/kbo-schedule.ts`의 상대 import에 컴파일 산출물 기준 `.js`를 명시했다.
- 교훈: 서버리스 코드는 로컬 dev뿐 아니라 컴파일 산출물의 Node 실행 경로도 검증한다.

## 2. 스코어보드 배경이 단색으로만 보임

- 증상: 야구 카드의 도형 레이어가 렌더링되지 않았다.
- 원인: 템플릿 검증은 ShapeLayer를 허용했지만 공용 캔버스 렌더러가 shape 타입을 처리하지 않았다.
- 해결: `CanvasStage.tsx`에 사각형·원 렌더링을 추가했다.
- 교훈: 기능별 우회 이미지 대신 공용 렌더러의 누락을 근본 수정한다.

## 3. 지정한 한글 폰트가 적용되지 않음

- 증상: IBM Plex Sans KR을 지정했지만 브라우저가 Malgun Gothic으로 조용히 폴백했다.
- 원인: 폰트 이름만 지정하고 실제 웹폰트를 로드하지 않았다.
- 해결: `index.html`에서 Google Fonts를 로드하고 폰트 준비 완료 시 캔버스를 다시 그렸다.
- 교훈: 폰트는 CSS 선언뿐 아니라 네트워크 로드와 실제 계산 스타일을 확인한다.

## 4. 오른쪽 워터마크가 배경에 가려짐

- 증상: 홈팀 워터마크가 보이지 않았다.
- 원인: 홈팀 배경 z-index가 워터마크보다 높았다.
- 해결: 두 배경을 같은 최하위 계층에 두고 워터마크를 그 위에 배치했다.



## 5. 되돌리기를 넣었더니 레이어 순서 변경이 이력을 망가뜨림 (2차)

- 증상(잠재): 레이어를 ▲▼로 옮긴 뒤 Ctrl+Z 하면 이전 상태가 이미 바뀌어 있을 수 있었다.
- 원인: 기존 `handleMoveLayer`가 레이어 객체의 `zIndex`를 제자리에서 수정해, 되돌리기 스냅샷과 같은 객체를 공유했다.
- 해결: `reorderLayers`가 항상 새 배열·새 객체를 만들도록 바꿨다. 이후 모든 레이어 변경(이동·그룹·정렬)을 불변 방식으로 통일했다.
- 교훈: 스냅샷 기반 이력을 도입하면 상태를 제자리에서 고치는 코드를 전부 찾아 불변으로 바꿔야 한다.

## 6. 새 웹폰트를 골라도 캔버스 글자가 안 바뀜 (2차)

- 증상: 글꼴 목록에서 "주아"를 골라도 캔버스 글자가 폴백 글꼴로 보였다.
- 원인: 캔버스(Konva)는 DOM과 달리 쓰이지 않은 웹폰트를 스스로 내려받지 않는다.
- 해결: 텍스트 레이어가 쓰는 글꼴을 `document.fonts.load`로 먼저 불러온 뒤 다시 그린다(`CanvasStage`의 `fontKey` 효과).
- 교훈: 캔버스에 쓰는 폰트는 "선언"이 아니라 "로드 완료"를 확인한다(3번과 같은 계열).

## 7. 레이어 드래그 정렬이 휴대폰에서 동작하지 않음 (2차)

- 원인: HTML5 드래그앤드롭 이벤트는 터치 입력에서 발생하지 않는다.
- 해결: `⋮⋮` 손잡이에 포인터 이벤트(`setPointerCapture` + `elementFromPoint`)를 써서 마우스·터치를 한 경로로 처리하고 `touch-action: none`을 지정했다.

## 8. 원·별 도형을 끌거나 키우면 위치가 어긋남 (2차)

- 원인: Konva의 원·별·다각형은 노드 좌표가 도형의 중심인데, 레이어 데이터는 좌상단 기준이었다.
- 해결: 이동은 "노드 이동량(dx, dy)"만 레이어에 더하는 방식으로, 변형은 중심→좌상단 변환을 거쳐 저장하도록 바꿨다. 원은 `Ellipse`로 바꿔 타원도 지원한다.

상세 재현과 커밋 이력은 `작업내역_체크리스트.md` §4를 기준으로 한다.
